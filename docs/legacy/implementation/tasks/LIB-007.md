# AI Task Brief — LIB-007 · OpenAI Interpreter/DraftGenerator y replay

**Estado:** pendiente, no implementada. **Origen:** [DAG V0](../DAG.md). **Repo:** `w0xter/libeen-sales-copilot`. **Rama sugerida:** `codex/lib-007`. **Responsable (rol):** Codex IA. **Gate:** G1. **Dependencias:** [LIB-003](LIB-003.md). Estas son asignaciones de trabajo propuestas, no branches/PR ya existentes.

## 1. Task ID

`LIB-007`. Antes de empezar, comprobar que todas las dependencias se hayan integrado y superado sus gates; trabajar en su propio worktree.

## 2. Objective

Implementar los adaptadores de IA para extraer hechos estructurados con evidencia y redactar propuestas permitidas, con modo replay determinista.

## 3. User / business value

Demuestra IA real donde aporta, permite comparar modelos cambiando `.env` y pruebas sin coste ni credencial.

## 4. Context

Proveedor confirmado OpenAI; modelo de pruebas `gpt-4.1-mini` en `OPENAI_MODEL`, modo `AI_MODE=openai` y `replay` explícito.

Fuentes que debe leer cuando sean relevantes: [AGENTS.md](../../../AGENTS.md), [contrato de integración](../../contracts/INTEGRATION_V0.md), [documentación funcional](../../README.md), [matriz AC](../ACCEPTANCE_MATRIX.md), [DAG](../DAG.md). No necesita Notion para ejecutar esta tarea.

## 5. Scope

Leer OPENAI_API_KEY y OPENAI_MODEL solo servidor; validación Zod/evidence; interpretación estructurada; redacción a partir de ActionProposal permitida; salida de replay marcada.

## 6. Out of scope

No transcripción audio, envío mensajes, acceso directo desde UI, modificación de prompts de dominio/contratos ni fallback silencioso.

No implementar funcionalidades no incluidas aunque sean técnicamente sencillas; preparar un Contract Change Request si se descubre una dependencia real nueva.

## 7. Functional requirements

Sin API key en modo real -> MODEL_UNAVAILABLE; salida inválida -> MODEL_OUTPUT_INVALID; source ausente -> EVIDENCE_INVALID; cambiar modelo no implica cambiar código.

## 8. Technical requirements

Timeout/errores tipados, evitar filtración de claves, no obedecer instrucciones de cliente como configuración; evaluación de texto por propiedades.

## 9. Constraints

Nunca inventar contenido de audio o afirmar que una redacción es autorización comercial. No invocar un modelo real en tests deterministas sin opt-in.

Reglas globales no dispensables: solo datos sintéticos; sin envío real ni aprobación financiera, con evidencia y revisión humana; trabajo limitado a su brief y rutas propias.

## 10. Acceptance criteria

- [ ] Replay es determinista y claramente etiquetado; sin clave funciona para tests.
- [ ] OPENAI_MODEL se lee desde entorno y su modificación no obliga a editar dominio ni adaptador.
- [ ] Ausencia de key, evidencia inválida, salida mal formada y timeout producen errores controlados.
- [ ] El draft respeta tipo de acción/restricciones y no emite aprobaciones ni garantías.
- [ ] Todos los cambios observables tienen tests apropiados (si aplica); los fallos y áreas no probadas están documentados.
- [ ] El resultado incluye un handoff con archivos, evidencias, validación y riesgos.

## 11. Validation expected

`pnpm test tests/unit/ai`, typecheck; smoke OpenAI real solo con clave local y coste/resultado documentados.

No asumir que todos los comandos existen: LIB-001 crea `pnpm test` y `pnpm typecheck`; ejecutar los realmente disponibles y reportar outputs verdaderos.

## 12. Risks and sensitive areas

Respuestas plausibles pero sin fuente y prompt injection; los contracts no se cambian unilateralmente.

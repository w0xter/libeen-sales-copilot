## 1. Task ID

`LIB-010`. Antes de empezar, comprobar que todas las dependencias se hayan integrado y superado sus gates; trabajar en su propio worktree.

## 2. Objective

Conectar interfaz y orquestador mediante operaciones HTTP o acciones servidor tipadas, sustituyendo mocks sin duplicar dominio.

## 3. User / business value

Permite demostrar el recorrido completo de Laura y visualizar estados/errores en una sola pantalla.

## 4. Context

Next 16.4.6; CaseView y eventos normalizados; rama UI fusionada y orquestador integrado previamente.

Fuentes que debe leer cuando sean relevantes: [AGENTS.md](../../../AGENTS.md), [contrato de integración](../../contracts/INTEGRATION_V0.md), [documentación funcional](../../README.md), [matriz AC](../ACCEPTANCE_MATRIX.md), [DAG](../DAG.md). No necesita Notion para ejecutar esta tarea.

## 5. Scope

Handlers validados, acceso servidor a OpenAI, refresco de vistas, revisión de estados stale y botones simulados.

## 6. Out of scope

No auth productiva, CRM/WhatsApp/calendar, websockets obligatorios, emisión automática ni escritura de políticas en UI.

No implementar funcionalidades no incluidas aunque sean técnicamente sencillas; preparar un Contract Change Request si se descubre una dependencia real nueva.

## 7. Functional requirements

El cliente nunca llama al SDK IA ni recibe API key; handlers rechazan payload inválido/revision conflict; approved no significa sent.

## 8. Technical requirements

Respuestas serializables CaseView, error codes seguros, manejo loading/retry; consulta documentación local de Next antes de usar convenciones.

## 9. Constraints

No permitir que un error HTTP o un reintento cree un segundo evento; no modificar archivos UI simultáneamente con rama LIB-008.

Reglas globales no dispensables: solo datos sintéticos; sin envío real ni aprobación financiera, con evidencia y revisión humana; trabajo limitado a su brief y rutas propias.

## 10. Acceptance criteria

- [ ] Selector y mensajes actualizan CaseView real y conservan evidence/progreso.
- [ ] El asesor puede editar/aprobar/descartar sin efectos externos ni M5 falso.
- [ ] Errores de modelo/red, conflictos y propuesta stale se muestran y permiten recuperación.
- [ ] Todos los cambios observables tienen tests apropiados (si aplica); los fallos y áreas no probadas están documentados.
- [ ] El resultado incluye un handoff con archivos, evidencias, validación y riesgos.

No asumir que todos los comandos existen: LIB-001 crea `pnpm test` y `pnpm typecheck`; ejecutar los realmente disponibles y reportar outputs verdaderos.

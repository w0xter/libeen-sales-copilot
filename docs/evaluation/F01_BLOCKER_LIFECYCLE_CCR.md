# CCR: evidenced blocker reassessment and lifecycle

**Status: proposed, not approved or implemented.** F-01's existing shared `Interpretation` contains only assertions, open blockers and warnings. `validateCandidates` rejects non-open blockers; the orchestrator merges blocker IDs into the snapshot. A later verifier cannot distinguish an earlier false label from a genuine objection that has since resolved, and omission cannot safely mean resolution. The existing `Blocker` status alone does not record why, by whom, or on which new evidence a closure occurred.

**Proposed contract change:** add an explicit, versioned reassessment or advisor-confirmed resolution operation identifying the existing blocker, disposition (unsupported original label versus subsequently resolved), source authority, and customer evidence references for the conclusion. Define an auditable event/decision record preserving the original observation and review history. Only an authorized, evidence-validated operation may alter open status; absence from a model response must never close it. Specify how a verifier's uncertainty holds analysis without misrepresenting it as a verified blocker.

**Compatibility and consumers:** this changes the Interpreter/Application boundary, validation, case snapshot/event persistence and CAS/idempotency handling, domain evaluation projections, UI/audit consumers, replay adapters and potentially existing serialized snapshots. It requires a version/migration strategy and integrator approval before edits to `src/contracts/**`. Existing sources must remain readable and legacy model blockers require a conservative migration/review path, not automatic closure.

**Required tests:** false legacy TRUST with evidence-based invalidation and retained history; genuine trust, OPT_OUT, URGENT and BINDING_CLAIM retained on omission; explicit supported resolution; invalid/advisor/audio/missing citations; verifier disagreement/outage; stale revision and duplicate events; concurrent analysis; unchanged replay fixtures and protected policy precedence.

**Blocked:** automatic, auditable removal of false or resolved legacy blockers and full Gate B acceptance. **Independent work:** transport diagnostics, safety verification with fail-closed behavior, correction handling, deterministic draft selection and their tests can continue without changing shared contracts. No contract or canonical fixture was modified by this iteration.
